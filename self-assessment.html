Overview

Completing the Computer Science program and developing this ePortfolio have allowed me to connect academic computer science principles with the practical responsibilities I perform in corporate information technology. My work has required me to support production systems, evaluate technical risk, communicate with stakeholders, and implement solutions that remain maintainable after deployment. The capstone strengthened my ability to explain those decisions through evidence rather than simply describing technologies I have used. The Weight Tracking App enhancements demonstrate this progression by showing how I moved an early Android application from a limited implementation toward a layered, testable, data-driven, and security-conscious solution.

My professional goals center on systems engineering, information security, automation, and software solutions that improve operational reliability. Coursework in software development, data structures, databases, secure coding, networking, and systems architecture helped me develop a broader view of computing. I no longer evaluate an application only by whether it runs. I evaluate how it handles invalid states, how its data is protected, how another developer can maintain it, how its design supports future requirements, and whether the solution provides measurable value to users and stakeholders.

Collaboration and Stakeholder Communication

Collaboration in computer science requires more than dividing work among team members. It requires shared terminology, clear expectations, traceable decisions, and communication adapted to the audience. In my professional work, I routinely translate technical issues for users, managers, vendors, and other IT staff. A stakeholder may need to understand business impact and risk, while a technical peer may need logs, reproduction steps, configuration details, and rollback procedures. This distinction has influenced how I document work and present recommendations.

The capstone code review provided a structured way to communicate the condition of the original artifact and the planned enhancements. I identified existing functionality, weaknesses in architecture and logic, security concerns, testing needs, and the trade-offs associated with the proposed changes. Instructor feedback functioned as an external review of those decisions. For the algorithms and data structures milestone, Professor Lusby specifically validated the use of least-squares linear regression with irregular time intervals, single-pass moving averages, Room entities, indexed queries, foreign-key relationships, password hashing, edge-case handling, and unit testing. Because the feedback identified no required corrections, I retained the implementation and incorporated the validation into the portfolio narrative rather than making unnecessary changes.

Software Engineering and Database Practices

The software engineering enhancement demonstrates my ability to improve architecture, maintainability, and separation of concerns. The original application concentrated substantial responsibility in a small number of components. The enhanced version uses a layered structure with Room entities and data-access objects, a repository, a ViewModel, focused user-interface components, and utility classes. This organization reduces coupling and makes the application easier to test and extend. It also shows that software quality depends on design decisions that support change, not only on the number of implemented features.

The database enhancement further developed the application into a multi-user data system with explicit relationships and stronger integrity rules. Room provides a structured persistence layer, while primary keys, foreign keys, indexed queries, and cascade behavior define how records are associated and maintained. User-scoped queries prevent one account's weight history from being mixed with another account's records. These changes demonstrate how database design supports both application correctness and privacy. They also reinforce the importance of schema planning, migration strategy, query behavior, and lifecycle management.

Algorithms and Data Structures

The algorithms and data structures enhancement transformed stored measurements into useful information. The application sorts records chronologically, computes moving averages, determines minimum and maximum values, evaluates trends, and applies least-squares linear regression using elapsed time rather than assuming evenly spaced entries. This design accounts for the fact that users do not always record their weight at regular intervals. The implementation also handles insufficient data, malformed dates, and near-zero regression denominators so that analytical features fail safely rather than producing misleading results.

The enhancement required explicit trade-off management. A larger moving-average window produces a smoother trend but reacts more slowly to recent changes. In-memory filtering is simple and appropriate for a modest personal dataset, but database-side filtering would scale better for substantially larger datasets. DiffUtil introduces additional implementation complexity but reduces unnecessary RecyclerView updates. Linear regression provides an interpretable trend and projection, but it cannot guarantee future outcomes. Describing these limitations is part of responsible computing because users and stakeholders need to understand what an algorithm can and cannot establish.

Security Mindset

Security is a cross-cutting design requirement rather than a final feature added after development. The enhanced application uses password hashing instead of storing plain-text passwords, separates user records, validates data preconditions, and applies database relationships that reduce inconsistent or orphaned records. The layered architecture also narrows responsibilities, making it easier to review where authentication, persistence, analytics, and presentation logic are handled. Unit tests for password utilities, date handling, and analytics help detect regressions in areas where incorrect behavior could affect confidentiality, integrity, or reliability.

The project also reinforced that one security control does not make an application fully secure. A production implementation would require careful selection of a password-hardening algorithm, unique salts, secure session handling, protected backups, comprehensive input validation, dependency review, and a tested migration path. Maintaining this distinction prevents overstating the security of a classroom artifact while still demonstrating a security-first approach to architecture and implementation.

Portfolio Integration and Employability

The artifacts in this ePortfolio fit together as stages of one engineering progression. The software engineering enhancement improves structure and maintainability. The algorithms and data structures enhancement adds efficient analytical capability and explains the associated trade-offs. The database enhancement strengthens persistence, relationships, user separation, and data integrity. The code review establishes the original condition of the artifact and the rationale for change, while the narratives explain what I learned and how the enhancements support the course outcomes.

Together, these components demonstrate that I can analyze an existing system, identify weaknesses, plan improvements, implement and test solutions, communicate design choices, and consider security throughout the lifecycle. My coursework and professional experience have prepared me to contribute in roles that require both technical depth and operational judgment. The ePortfolio provides concrete evidence of my ability to build computing solutions that are understandable, maintainable, secure, and aligned with user and organizational needs.
