CS 499 · Enhancement Two

Algorithms and Data Structures

Weight Tracking App enhancements using chronological data processing, single-pass analytics, least-squares linear regression, efficient list differencing, and searchable history.

Artifact overview

The artifact is an Android weight-tracking application created earlier in the Computer Science program. I selected it because the original application stored useful records but did not fully transform those records into reliable, decision-supporting information. The enhancement improves computational correctness, analytical value, and runtime behavior while preserving a practical user-facing purpose.

Enhancement summary

Chronological correctness

Records are interpreted by normalized date and creation time rather than row identifier, preventing back-dated entries from being misclassified as the newest measurement.

Single-pass analytics

Moving averages, minimum values, and maximum values are calculated with linear traversal, keeping the implementation readable and efficient for the application’s expected dataset size.

Regression trend analysis

Least-squares linear regression models weight against elapsed days, correctly accounting for irregular intervals between measurements and reporting a weekly rate of change.

Efficient presentation structures

History filtering creates a derived in-memory collection, while DiffUtil computes minimal RecyclerView changes instead of rebinding the complete list.

Algorithmic design and trade-offs

The regression slope is computed as (nΣxy − ΣxΣy) / (nΣx² − (Σx)²). The implementation checks preconditions, protects against a near-zero denominator, and uses floating-point tolerance when classifying a slope as stable. A configurable moving-average window allows a deliberate trade-off between smoothing and responsiveness. In-memory history filtering is appropriate for the current dataset size, while database-side search would be a logical future optimization if the record count grows substantially.

Professor Lusby characterized the narrative as exceptionally thorough and clear and specifically validated the use of least-squares regression for irregular time intervals, single-pass moving averages, complexity and trade-off analysis, Room structures, indexed queries, foreign-key behavior, password hashing, edge-case handling, data preconditions, and unit testing. Because the feedback identified no corrective deficiencies, incorporation consisted of preserving the validated implementation and presenting the evidence more clearly in the ePortfolio.

Reflection

This enhancement reinforced that an algorithm is not correct merely because it produces a result. Correctness depends on ordering assumptions, valid preconditions, treatment of malformed or insufficient data, numerical stability, and tests that exercise boundary conditions. I also learned to frame optimization decisions in context: an O(n) traversal is appropriate for a modest local dataset, while more complex indexing or database-side computation would introduce maintenance cost without a corresponding present benefit.

The work most directly supports the course outcomes related to professional communication, algorithmic problem solving, well-founded computing practices, and security-conscious design. Collaboration and stakeholder communication are demonstrated more fully through the code-review video, instructor feedback process, and final professional self-assessment.
